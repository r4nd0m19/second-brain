# Feature Specification: F1 核心问答（core-qa）

**Feature Branch**: `001-core-qa`（目录；项目暂未启用 git）

**Created**: 2026-10-01

**Status**: Implemented（核心链路已实现并验收，收尾批次进行中）

**Input**: "让 second-brain 从零转起来的最小可用闭环：文件上传入库、对话式问答（带出处）、模型兜底、兜底回写。"

## 背景与问题 *(mandatory)*

用户的资料（书籍、文档）越存越多，但检索困难、等于没存；通用 AI 虽强，却没有个人资料的上下文，每次都要从零解释背景。

本 feature 打通 second-brain 的第一条主干，让系统从零到可用：

> **上传资料 → 入库可检索 → 对话提问 → 命中：基于资料作答并标注出处 / 未命中：外部模型兜底 → 兜底问答回写入库**

它是验证核心价值假设的第一步（"对自己资料里的细节，随问随答"），也是后续能力（浏览器采集、主动洞察）的地基。

项目级背景见 `.specify/memory/project.md`（§3 痛点、§4 Goals G1/G4、§10 验收场景 1/3/4）。

## Clarifications

### Session 2026-10-01

- Q: 回答中标注的"出处"需要精确到什么程度？ → A: 资料名 + 位置（章节/段落；PDF 含页码）+ 可展开的原文引用片段
- Q: 同一资料重复上传（完全相同或更新版本）时怎么处理？ → A: 内容完全相同 → 提示已存在并跳过；内容不同 → 作为新资料入库（同名允许并存，旧版由用户手动删除）
- Q: 库里只有"弱相关"内容时怎么回答？ → A: 模型兜底回答为主（明确标注来源），同时附"库中可能相关"提示，弱相关内容不混入主回答
- Q: 兜底回写的对话记录要不要也显示在"资料列表"里？ → A: 不显示 —— 资料列表只列上传件；对话记录在对话历史中查看与管理；检索层两者互通（二次命中不受影响）
- Q: v1 备份做到什么程度？ → A: 本地每日自动备份（数据库 dump + 原文件增量）+ 自动同步一份到异地对象存储；备份范围 = 数据库 + 原文件

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 上传资料并基于内容问答 (Priority: P1) 🎯 MVP

用户上传书籍/文档（如《SDD实战》），入库完成后用自然语言提问资料中的内容；系统在自己的库中找到支撑内容，给出回答并标明出处（哪份资料、什么位置）。

**Why this priority**: 产品的核心价值主张——"你的资料，随问随答"。没有它其余一切无从谈起，构成最小可用产品（MVP）。

**Independent Test**: 上传一份含明确内容的文档 → 提一个只有该文档能回答的问题 → 检查回答正确且出处指向该文档。

**Acceptance Scenarios**:

1. **Given** 库为空，**When** 用户上传一份文本型文档并等待入库完成，**Then** 该资料出现在资料列表中且状态为"已入库"
2. **Given** 资料已入库，**When** 用户询问该资料中的细节，**Then** 回答基于资料内容，且标注出处（资料名 + 位置）
3. **Given** 资料已入库，**When** 用户询问该资料完全未涉及的话题，**Then** 系统不编造"资料里有这个答案"（走模型兜底并明确标注来源；若存在弱相关内容，附"库中可能相关"提示）
4. **Given** 资料已入库，**When** 用户下载该资料的原文件，**Then** 所得文件与上传时完全一致
5. **Given** 用户上传一个无法解析的文件（如扫描版 PDF），**When** 查看资料列表，**Then** 该文件已保存、状态为"无法解析"、原文件可下载，且系统明确说明内容暂不可读

---

### User Story 2 - 库外问题由外部模型兜底 (Priority: P2)

当个人库中没有相关内容时，系统调用外部 AI 模型基于通用知识回答，并明确标注"此回答来自模型通用知识，非你的资料"。

**Why this priority**: "像 ChatGPT 一样的体验"要求任何问题都有回应；兜底保证体验完整。可独立测试（空库即可验证）。

**Independent Test**: 在空库中提问（或问明显的库外问题），获得可用回答，且回答标注来源类型为"模型知识"。

**Acceptance Scenarios**:

1. **Given** 库中无相关内容，**When** 用户提问，**Then** 得到外部模型生成的回答，且明确标注来源类型
2. **Given** 外部模型服务不可用，**When** 用户提问，**Then** 系统明确提示失败与可重试，用户已上传的资料不受影响

---

### User Story 3 - 兜底问答回写闭环 (Priority: P3)

库外问题被回答后，该问答自动存入个人库；同一问题再次提问时，系统直接命中库中内容（标注为"来自你之前的对话"），不再调用外部模型。

**Why this priority**: 数据自增长闭环——用得越久，库越丰富（项目目标 G4）。

**Independent Test**: 问一个库外问题 → 再次问同一问题 → 第二次回答来自库且不触发外部模型调用（可通过来源标注验证）；也可手工构造一条既往对话记录，独立验证命中路径。

**Acceptance Scenarios**:

1. **Given** 用户刚问过一个库外问题并被兜底回答，**When** 再次问同一问题（或强相关），**Then** 回答来自库中既往对话记录，并标注该来源类型
2. **Given** 回写发生，**When** 用户查看对话历史，**Then** 能发现该问答已被记录且可追溯

---

### User Story 4 - 可安装 Web 应用（双端） (Priority: P4)

用户在 Windows 电脑浏览器与 Android 手机上把系统"安装"为应用（独立窗口 / 主屏图标），像原生 App 一样使用。

**Why this priority**: 双端可用是项目硬需求；浏览器直接访问已能满足基本使用，"安装"形态是体验增强。

**Independent Test**: 在 Windows 与 Android 浏览器分别完成"安装 → 打开 → 完成一次问答"。

**Acceptance Scenarios**:

1. **Given** 用户在 Windows 浏览器访问系统，**When** 执行安装，**Then** 以独立应用窗口打开并可用
2. **Given** 用户在 Android 浏览器访问系统，**When** 添加到主屏幕，**Then** 从主屏图标打开后以应用形态（无浏览器地址栏）使用

---

### Edge Cases

- 上传无法解析的文件（不支持的格式 / 扫描版 / 损坏文件）→ 仍保存并登记（保留原文件，状态"无法解析"），明确告知用户"已保存，但内容暂无法读取"；可下载原文件
- 0 字节空文件 → 拒绝上传并明确提示（不登记）
- 上传重复文件 → 内容完全相同：提示已存在并跳过；内容不同（含同名新版）：作为新资料入库
- 扫描版（图片型）PDF（无文本层）→ 保存并登记为"无法解析"，提示用户；OCR 列入 backlog（B4）
- 超大文件（如数百 MB）→ 入库异步进行，期间可继续对话，完成后通知
- 资料删除后，引用了该资料的既往对话 → 引用处标注"来源已删除"，不报错
- 同一问题命中库中多条资料 → 回答融合多个来源，并列出多个出处
- 库中只有弱相关内容 → 模型兜底为主 + 附"库中可能相关"提示（见 FR-007）
- 多轮追问 → 结合上文语境理解（如："那本 SDD 书里怎么说的？"中的"那本"指代明确）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 用户可上传常见文档格式（至少含 PDF、EPUB、TXT、Markdown、DOCX）并解析其文本内容；其他类型的文件同样可上传保存（无法解析时的登记规则见 FR-014）；内容完全相同的重复上传去重（提示并跳过），同名但内容不同视为新资料
- **FR-002**: 解析完成后内容进入可检索的库；解析状态对用户可见（处理中 / 已入库 / 无法解析）
- **FR-003**: 用户可查看已上传的资料列表，并可删除任意资料（连同其全部内容块、索引与原始文件）
- **FR-004**: 用户可在对话界面以自然语言连续提问，系统理解多轮上下文（超长对话按上下文预算截断更早历史，不丢失库中数据）
- **FR-005**: 提问时系统优先检索个人库；命中时基于库内容生成回答
- **FR-006**: 基于库内容的回答必须标注出处：回答正文中的引用编号（[N]）可直接点击跳转原文位置（见 FR-016）；出处列表含资料名 + 位置（章节/段落；PDF 含页码）+ 可展开的原文引用片段
- **FR-007**: 库中无相关内容时，调用外部 AI 模型生成回答，并明确区分"来自模型通用知识"；弱相关判定基于可配置的相关度阈值，弱相关内容不混入主回答，以"库中可能相关"提示附后
- **FR-008**: 模型兜底产生的问答自动写入库，来源记为"与第二大脑的对话"
- **FR-009**: 对话历史持久保存，用户可查看与管理历史会话；对话记录不出现在资料列表中（资料列表只列上传的文件）
- **FR-010**: 系统仅限本人访问（单用户认证）
- **FR-011**: 删除权：用户可删除任意入库内容（资料在资料列表删除、对话记录在对话历史删除）；删除在检索与历史引用中同步生效；删除内容不再进入后续备份
- **FR-012**: 系统以可安装 Web 应用形式提供：在 Windows 与 Android 浏览器中可安装为应用形态
- **FR-013**: 系统保留上传文件的原始版本；用户可随时下载原文件，所得内容与上传时完全一致（不改动、不转码）
- **FR-014**: 无法解析的文件不拒绝、不丢弃：仍保存并登记（保留原文件、状态标注"无法解析"；判定规则：无文本层 / 格式不支持 / 损坏或加密），在资料列表中可见且可下载；对话中涉及该文件时，系统能告知其存在、但内容暂不可读
- **FR-015**: 用户可在浏览器内直接浏览原文件（无需下载）：PDF 与 EPUB 提供内置阅读视图，TXT/Markdown 提供文本视图；"无法解析"的文件同样可浏览原文件；其余格式（如 DOCX）保持下载方式（2026-10-03 增补：EPUB 阅读视图提供**目录（TOC）导航**、**页码显示**（按位置索引估算，支持**按页跳转**）与键盘 ←/→ 翻页——章内焦点同样生效）
- **FR-016**: 回答中的"出处"可点击跳转到原文件中的对应位置：PDF 定位到页码、文本类定位并高亮引用段落、EPUB 定位到引文所在页并高亮引文（尽力而为：逐级退回"引文所在章节 → 文档开头"）；从对话进入的浏览页可直接返回对话；资料已被删除时给出"来源已删除"明确提示
- **FR-017**: 每轮对话记录模型 token 用量并估算费用（随消息存入数据库），并在回答下方以小字展示（↑输入 ↓输出 tokens · 估算金额）
- **FR-018**（2026-10-02 增补）: 资料列表支持**分页**（每页 20 条）、**搜索**（标题 + 正文子串，含命中片段）与**排序**（上传时间 / 文件名 / 大小，升/降序）；查询状态进 URL，刷新/返回不丢
- **FR-019**（2026-10-02 增补）: 对话历史支持**全文搜索**（用户与助手消息正文）：结果按会话聚合（标题 + 命中片段 + 命中数），点击打开会话并定位到命中消息（短暂高亮）；对话侧栏可收起（状态记忆）
- **FR-020**（2026-10-02 增补）: **既往对话来源的回答**：正文中的引用标记 [N] 应映射回当时的原始出处（启发式追溯，无法解析时降级为纯文本、不得误指）；出处支持**回到原对话**（跳转会话并定位到原始消息、短暂高亮）；读取历史消息时对存量数据同样生效
- **FR-021**（2026-10-02 增补）: **低置信多查询重试**：检索无强命中时，将问题改写为 2-3 条检索变体并逐一检索、按块合并取最高分；若变体召回强命中则正常作答（本地优先原则不变），否则维持原有降级路径；改写失败静默跳过（不阻塞、不改变现有行为）
- **FR-022**（2026-10-03 增补）: **查询规划（工具取数）**：取数方式由 LLM 规划器以工具调用决定（语义检索 / 浏览清单 / 联网搜索，最多 3 个，可按需组合或全不选）；句式规则路由（清单/语义意图词表、显式联网指令正则）全部退役；规划失败或未选择工具时回退"默认语义检索"基线（规划器是基线之上的优化，不得阻塞问答）；非语言性内容块（SVG 坐标/CSS 数字海等）不入索引（防"假强命中"）
- **FR-023**（2026-10-03 增补）: **界面中英切换**：顶栏提供语言切换（主题钮旁，按钮显示目标语言）；首次访问跟随浏览器语言，手动切换后本地记忆（跨刷新/跨页面保持）；覆盖全部界面文案（资料库 / 对话 / 阅读器 / 快照 / 登录及通用组件）；切换不改变 URL 与既有深链。范围排除：回答内容（模型按提问语言作答）、后端错误消息、静态页面元数据

### Key Entities

- **资料（Document）**: 用户上传的文件；属性：名称、格式、大小、上传时间、解析状态、来源类型（上传 / 对话；对话来源仅用于检索与出处标注，不显示在资料列表）、原始文件（服务器保留、随时可下载，与上传件字节级一致）；唯一性：内容判重（完全相同的重复上传不入库），同名不同内容可并存
- **内容块（Content Chunk）**: 资料的检索单元；属性：所属资料、文本、位置（章节/段落/页码）、原文引用片段
- **对话（Conversation）**: 一次会话；属性：标题、创建时间
- **消息（Message）**: 问答条目；属性：问题、回答、来源类型（库 / 模型知识 / 既往对话）、引用列表、时间
- **用户**: 单用户（本人）

## Non-Goals（本次不做什么） *(mandatory)*

- 浏览器自动采集（F2）与 Android 采集（F3）—— 本 feature 只含手动上传文件
- ChatGPT 历史导入（backlog B1）
- 主动洞察与建议（backlog B3）
- 多用户 / 协作 / 分享
- 原生 App（用可安装 Web 应用代替）
- 本地大模型（全部走外部模型）
- 扫描版（图片型）PDF 的内容识别（OCR）—— v1 保存登记、内容暂不可读，不做识别；OCR 列入 backlog

## Non-Functional Requirements *(include if applicable)*

### Performance
- 提问后 10 秒内开始出现回答（流式呈现；命中与兜底路径均适用）
- 库内容量到 10 万块规模：常见检索 P95 ≤ 2 秒
- 大文件解析不阻塞对话使用（后台进行）

### Reliability
- 已入库内容不丢失：**本地每日自动备份（数据库 + 原文件）+ 自动同步异地对象存储**（v1 组成部分）；故障后可从备份完整恢复
- 外部模型故障不影响已上传资料与历史对话的浏览；仅兜底问答暂不可用并明确提示
- 解析失败有可读的错误反馈，可重试
- 入库流程可安全重试（幂等，不产生重复内容）
- 磁盘空间不足时拒绝上传并明确提示

### Security
- 仅本人可访问：认证 + 全程 HTTPS；登录失败限速（默认 5 次/15 分钟，可配置）
- 模型服务密钥仅存服务端，绝不暴露给客户端
- 调用外部模型时仅发送检索命中的必要片段，不整库外发（入库 embedding 阶段的全量外发为例外，已登记于 plan.md Complexity Tracking）

### Scalability
- 按单人使用规模设计；数据模型为将来多用户留余地

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 上传一份 300 页以内的文本型书籍，5 分钟内完成入库并可被检索到
- **SC-002**: 针对已入库资料设计的 ≥20 题样例问题集（含标准答案与出处对照表）中，≥80%（≥16 题）得到基于库内容、且出处正确的回答
- **SC-003**: 库外问题 100% 获得回答，且来源类型（库 / 模型知识）标注正确
- **SC-004**: 兜底问答的"二次提问"场景中，100% 不再触发外部模型调用（通过回答来源标注与模型调用日志验证）
- **SC-005**: 在 Windows 与 Android 上均可完成"安装 → 打开 → 完成一次问答"全流程
- **SC-006**: 对任一已入库资料，下载所得原文件与上传件校验一致（抽查 100% 通过）
- **SC-007**: 无法解析的文件 100% 被登记保存（不丢失）且可下载原文件
- **SC-008**: 每日自动生成备份且异地副本存在；备份恢复演练 1 次通过（判定：从最近备份在干净环境重建数据库与原文件，抽查 10 份资料与 5 条对话完整一致）

## Assumptions

- 单用户使用；认证 = 单账号 + 会话 Cookie（HttpOnly），登录限速见 NFR Security
- v1 支持文本型文档；不支持扫描版 PDF（图片型），检测到时明确提示用户
- 外部 AI 模型通过服务端接入，模型可配置（默认成本优先），密钥由用户提供
- 单文件大小上限默认 200MB，后续可调
- 以中文使用为主（资料可含英文内容）
- "出处"标注格式：资料名 + 位置（章节/段落；PDF 含页码）+ 可展开的原文引用片段；点击出处跳转原文位置见 FR-016
- 上传的原文件在服务器保留并可下载；在线预览见 FR-015（PDF/EPUB/文本）；更广格式的预览（DOCX 转换等）仍为后续增强项
