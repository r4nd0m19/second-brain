## 背景与问题 *(mandatory)*

**现状怎么做**：每天的信息摄入大头是浏览网页（教程、文档、文章）。想找回"几天前看过的那篇教程里某个细节"，只能靠浏览器历史（仅能搜标题/URL 字符串）、书签、或记忆——**内容本身找不回**——或主动做剪藏/收藏，繁琐到无法坚持。

**痛点**：看过 = 没看过。通用 AI 不知道你看过什么，每次都要从零解释背景；浏览器历史是"地址簿"而非"记忆"。

**本 feature 要解决什么**：让浏览**自动**沉淀为可对话的记忆——装上扩展后什么都不用做，看过的网页正文自动进入第二大脑；几天后可以像问书一样问："我 3 天前看的 Next.js 教程里，中间件的鉴权是怎么写的？"回答基于那篇网页，并附出处（标题 / 链接 / 浏览时间）。

这是 F1（上传资料问答）之后的第二个数据源（项目愿景 G2 与场景 1）；采集可行性调研见 project.md 附录 C（Hoardy-Web / ArchiveBox 先例）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览即自动入库，日后随问随答 (Priority: P1) 🎯 MVP

用户安装浏览器扩展并连接自己的第二大脑后，**日常浏览不做任何额外操作**：访问的网页正文自动入库。几天后提问当初看过的内容，系统基于网页正文作答，并给出出处（网页标题 + 链接 + 浏览时间）。

**Why this priority**: 这是本 feature 的全部价值主张——"自动采集 + 可召回"。没有它，其余一切（管理、时间回找）都无从谈起。

**Independent Test**: 装上扩展 → 浏览一篇含明确内容的网页 → 在对话里问该内容 → 回答正确、出处指向该网页。

**Acceptance Scenarios**:

1. **Given** 扩展已安装并连接成功，**When** 用户访问一篇普通内容网页并真实阅读（停留 ≥10 秒或滚动过半），**Then** 该页正文被自动采集入库，全过程无需任何手动操作
2. **Given** 某网页已被采集，**When** 用户提问该网页中的细节，**Then** 回答基于该网页内容，出处包含网页标题、链接与浏览时间
3. **Given** 提问涉及的内容库里没有，**When** 提问，**Then** 按 F1 既有逻辑兜底（模型知识回答 + 来源标注），不虚称"你看过"

---

### User Story 2 - 采集的可见、可控与隐私边界 (Priority: P2)

用户能看见采集了什么（透明）、能删掉任意一条、能把敏感站点加入黑名单（从源头不采集）、能一键暂停采集。这是"敢长期开着它浏览"的前提。

**Why this priority**: 涉及隐私底线（constitution IV 数据最小暴露 / V 数据可控）——黑名单必须从源头不产生数据，删除必须全链路生效。没有这层信任，用户不会开着它上网。

**Independent Test**: 把某域名加入黑名单 → 访问该域名站点 → 确认无任何采集（含元信息）；删除一条已采集网页 → 检索与出处同步消失。

**Acceptance Scenarios**:

1. **Given** 黑名单中包含某域名，**When** 用户访问该域名下的页面并停留，**Then** 不产生任何采集数据（连 URL/标题等元信息也不落库）
2. **Given** 一条已采集的网页，**When** 用户在资料区删除它（或按时间范围清理一批），**Then** 检索、出处、备份策略均同步生效，不再出现
3. **Given** 用户暂停采集，**When** 继续浏览，**Then** 不产生新采集；恢复后继续工作
4. **Given** 用户想知道"它到底采了啥"，**When** 查看资料区的浏览器来源筛选，**Then** 可逐条看到标题、网址与浏览时间

---

### User Story 3 - 时间维度回找 (Priority: P3)

"我上周都看了些什么？""3 天前看过的那篇讲 diff 算法的文章再找出来"——以浏览时间为线索的找回。

**Why this priority**: 时间是最好的检索线索之一，是场景 1（"3 天前看过…"）的自然延伸；但语义召回（US1）已覆盖大部分内容场景，时间查询属增强。

**Independent Test**: 浏览数篇网页 → 提出时间相关的问题 → 得到符合该时间范围的网页清单/内容。

**Acceptance Scenarios**:

1. **Given** 数日内浏览了多篇网页，**When** 问"我昨天看过哪些网页？"，**Then** 列出该时段浏览的网页（标题 + 时间）
2. **Given** 同一主题多次浏览，**When** 问"最近看过关于 X 的文章是哪篇？"，**Then** 按时间给出结果

---

### Edge Cases

- **页面正文提取失败**（JS 渲染未完成就关闭 / 非文章型页面 / 反爬）：不产正文，**仅保留标题与网址元信息**供回溯（可配置关闭）——绝不影响浏览本身
- **同一 URL 反复访问**：覆盖更新为最新内容与快照，保留最近访问时间与访问次数；v1 不保留历史版本
- **高频互动页**（论坛、社交媒体信息流）：由黑名单 + 采集触发阈值（停留 ≥10 秒或滚动过半）共同控制噪音
- **服务器不可达**：采集进本地队列，自动重试补传；期间浏览无感、数据不丢
- **需登录才能看的页面**（个人后台、内网系统）：按"浏览器当前可见内容"采集；高敏系统建议加黑名单（文档明示提醒）
- **无痕/隐私窗口**：不采集（扩展默认不注入）
- **多标签并行**：各自独立采集，互不影响
- **点了 PDF / 视频等非网页链接**：不受影响（照常下载/播放），本 feature 不采集非 HTML 正文

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 用户可在 Chrome / Edge（桌面版）安装采集扩展，并用**专属凭据**（可单独吊销，仅具采集写入权限）连接自己的第二大脑
- **FR-002**: 用户访问网页并**真实阅读（停留 ≥10 秒或滚动过半，阈值可配置）**时，扩展**自动提取正文**（标题、正文文本、网址、浏览时间）并上传入库；提取在浏览器本地完成，无需任何手动操作；未达阈值的访问不产生采集
- **FR-003**: 浏览器采集的内容作为**新的来源类型**进入既有检索体系；对话引用时标注来源为浏览网页，附标题 / 链接 / 浏览时间，并可跳转回原网址
- **FR-004**: 用户可维护**黑名单**（站点/域名级）并可**一键暂停**采集；黑名单站点从源头不采集——不产生任何数据（含元信息）
- **FR-005**: **去重与更新**：同一网址重复访问覆盖更新（记录最近访问时间与访问次数）；不同网址各自独立保留
- **FR-006**: **离线容错**：服务器不可达时本地队列缓存并自动重试补传；采集不阻塞浏览
- **FR-007**: **可见与可控**：浏览器来源内容在管理界面按来源筛选可见；支持单条删除与**按时间范围批量清理**（constitution V）；删除在检索与出处中同步生效
- **FR-008**: 采集**透明**：扩展界面显示今日采集计数与状态（连接/暂停/队列积压）
- **FR-009**: **解耦**（constitution VI）：采集链路（扩展、上传、入库）的任何故障不影响 F1 核心问答的可用性
- **FR-010**: 采集内容与既有资料**同库同检索**；命中判定、弱相关提示与兜底逻辑沿用 F1 规则，不做特殊对待
- **FR-011**: 系统记录并展示每次采集的浏览时间（首次 / 最近），供时间相关问答与列表排序使用
- **FR-012**: 支持基于浏览时间的回找：既支持元信息清单（"我上周看过哪些网页"→标题+时间列表），也支持**正文语义 + 时间过滤的组合检索**（"上周看过的文章里关于 X 的部分"）
- **FR-013**: 系统**保留原始页面快照**（连同正文与元信息）以支持高保真重现（防链接失效/改版）；快照与正文同等受黑名单（源头不采）、单条删除与按时间清理约束，删除在备份中同步生效
- **FR-014**: 快照采集需**限流**（并发/体积上限可配置），确保不影响正常浏览体验

### Key Entities *(include if feature involves data)*

- **网页条目（WebPage）**：一条采集记录；属性：网址、标题、正文、首次/最近浏览时间、访问次数、来源类型（浏览器）；可被单条删除或按时间范围清理
- **采集凭据（CaptureToken）**：扩展连接第二大脑的专属凭据；可吊销、最小权限（仅采集写入）
- **黑名单规则（BlockRule）**：域名/站点级；从源头阻止采集；含全局暂停开关
- **采集队列（本地）**：扩展侧的待传/重试队列（浏览器本地存储，非服务器实体）

## Non-Goals（本次不做什么） *(mandatory)*

- **Android 采集** —— F3 阶段；且系统限制使 Chrome 安卓 / App 内置浏览器（微信等）不可及（附录 C）
- **ChatGPT 历史导入** —— backlog B1
- **PDF / 视频等非 HTML 内容的自动采集** —— 点击下载/播放照旧，不拦截不入库（网页快照仅限 HTML 页面本身）
- **全站爬取 / 主动抓取** —— 只采"你看过的"，不主动爬站点
- **采集内容的编辑** —— 采集即原样保存，只支持查看与删除
- **多用户 / 多人共享采集** —— 沿用单用户；架构留路（constitution VII）
- **采集统计报表 / 浏览行为分析** —— 不属本 feature（主动洞察见 backlog B3）

## Non-Functional Requirements *(include if applicable)*

### Performance
- 采集对页面加载**无可感影响**（提取本地完成、上传异步后台）
- 单页入库为秒级（网页正文无需重解析）；入库延迟不影响"浏览后即可再问"的整体体验
- 检索响应不因新增来源类型而降级（沿用 F1 压测基线）

### Reliability
- 采集数据不丢：本地队列 + 自动重试；服务器故障 ≤30 分钟期间的数据在恢复后完整补传
- 采集链路故障与 F1 问答完全解耦（FR-009）

### Security
- 扩展使用**专属凭据**（可吊销、最小权限），不携带主账号会话
- 黑名单站点从源头不采集；无痕窗口不采集；传输全程 TLS
- **快照可能包含页面上的敏感信息**（如登录后的表单回显）——黑名单是唯一源头防线（文档明示）；快照与正文同等受删除/清理约束（含备份同步）
- 采集内容支持全量清理（按时间范围），删除在备份策略中同步生效

### Scalability
- 按个人规模设计（每天几十到数百页）；沿 F1 数据模型的多用户留路（owner 归属）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 浏览一篇普通文章后 **30 秒内**，可在对话中间出其细节——全程无任何手动操作（100% 抽样通过）
- **SC-002**: 针对"≥3 天前浏览过的网页"设计的 ≥10 题样例中，**≥80%** 能找回正确内容且出处（标题/链接）正确——对齐项目目标 G2 的验收案例
- **SC-003**: 黑名单站点产生的采集数据量为 **0**（含元信息，抽查 100% 通过）
- **SC-004**: 任意一条采集内容删除后，检索与出处**同步消失**（100% 抽检通过）
- **SC-005**: 服务器不可达 30 分钟期间浏览的内容，恢复后 **100% 补传**、不丢失
- **SC-006**: 开启采集前后，日常浏览体验无感知差异（页面加载/滚动主观无感 + 无阻塞等待）
- **SC-007**: 时间类问题（如"我上周看过哪些网页"）返回结果与实际行动**一致**（抽样核对）；语义+时间组合问题（"上周看过的 X"）命中正确
- **SC-008**: 已采集页面在原链接失效/改版后，仍可依赖**快照**查看当初内容（抽检 100% 通过）

## Assumptions

- 仅覆盖 **Chrome / Edge 桌面版**（Manifest V3 生态）；用户日常以其中一个为主力浏览器
- 服务器地址与采集凭据由用户在扩展中配置一次（不内嵌任何私密信息在扩展里）
- 采集触发为**阅读阈值制**（停留 ≥10 秒或滚动过半，阈值可配置）——对 project.md"被动全量捕获"决策的修正：以"真实阅读"为采集信号，过滤误点与快速跳转
- "可见内容"以浏览器当前渲染为准（含登录后页面）；高敏系统的防护方式是**黑名单**而非逐页判断
- 与 F1 共用同一 API 与认证边界；凭据走最小权限设计
- 正文/快照的存储上限、队列上限、单页最大尺寸、快照限流参数等，在 plan 阶段细化（取行业常规默认）
- 扩展分发：自用优先可旁加载 / 私有发布；商店公开分发不在本 feature 承诺内

## Clarifications

### Session 2026-10-02

- Q: 采集触发粒度——访问即采，还是停留阈值？ → A: **停留 ≥10 秒或滚动过半才采**（噪音最低，信任浓度高）；短查询类页面可能漏采，接受；阈值保留可配置
- Q: 时间检索深度——仅元信息清单，还是与正文语义组合？ → A: **正文语义 + 时间过滤组合**（"上周看过的文章里关于 X 的部分"类问题成立）
- Q: 原始页面快照——仅存正文，还是保留快照？ → A: **保留原始页面快照**（高保真重现、防链接失效/改版；接受存储与隐私成本，配套限流 FR-014 与黑名单源头防线）
