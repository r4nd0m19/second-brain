# Feature Specification: Android 端采集（F3）+ 分享补盲

**Feature Branch**: `005-android-capture`

**Created**: 2026-10-03

**Status**: Draft

**Input**: User description: "F3 Android 端采集（接力 F2 Windows 采集）+ 分享补盲。① Firefox for Android 扩展：现有 Chromium MV3 采集扩展做 Firefox 双端适配，全自动采集手机 Firefox 内浏览页面，复用既有采集 token API 入库；含自用分发流程（AMO unlisted 私密签名 → 手机 Firefox 安装）。② PWA 分享面板（Web Share Target）补盲：Android Chrome 等支持分享目标的浏览器/App 内，「分享 → 第二大脑」→ 服务端抓取该 URL 正文入库（browser 来源）。边界（沿用并修订原 Non-Goal）：微信等 App 内置浏览器仍不做全自动采集，仅能手动分享；Firefox Android 不支持 PWA 安装（全自动与分享补盲天然互补覆盖两种浏览器）。关联：复用服务端抓取能力与采集端点；真机联调依赖用户手机；手机端 PWA 安装/适配复核（001 T029/T030）可随本 feature 结清。"

## 背景与问题 *(mandatory)*

项目双端目标（project.md，2026-10-01 决策）：**Windows 电脑 + Android 手机全自动采集**。桌面端（F2）已交付——Chrome/Edge 扩展"浏览即入库"；但**手机端至今没有采集路径**：手机上读过的页面进不了库，而手机恰是碎片阅读的主场——缺口直接违背"双端一致"的项目前提，也是路线图 F1→F2→F3 中唯一未开工的 F。

既定方案（2026-10-01 调研定案）：Android 侧走 **Firefox for Android + 扩展**（全自动）；并已登记边界：Chrome 安卓 / 微信等内置浏览器内的浏览采不到。本次在既定方案上**补一个轻量入口**：借 Android 系统**分享面板**（任意浏览器/App 内「分享 → 第二大脑」）把页面存入库。两种浏览器形态天然互补（Firefox 安卓不装 PWA、Chrome 安卓不装扩展），把原"盲区"从"完全采不到"缩小为"微信内需手动分享"。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手机 Firefox 浏览自动入库 (Priority: P1)

用户在 Android 手机上用 Firefox 阅读网页（教程/文章/文档），系统**自动**把页面（标题/链接/浏览时间/正文）存入第二大脑——与桌面端语义完全一致：之后在任意端都能检索命中、作为出处引用、出现在浏览记录与时间清单里。

**Why this priority**: 这是 F3 的本体——"双端全自动采集"的最后一块；不做它，手机上的数字生活仍在库外。

**Independent Test**: 手机 Firefox 连续浏览若干页面 → 桌面端检索其中内容能命中、浏览记录出现对应条目、时间清单正确。

**Acceptance Scenarios**:

1. **Given** 手机 Firefox 已安装采集扩展并配置凭据，**When** 浏览任意网页并停留片刻，**Then** 该页（标题/URL/时间/正文）入库，桌面端可检索、可引用
2. **Given** 浏览的页面命中采集排除规则（黑名单，沿用 F2 语义），**When** 浏览该页，**Then** 不入库（从源头不采集）
3. **Given** 网络不可达或服务端故障，**When** 浏览页面，**Then** 采集静默跳过/待重试，**浏览体验零打扰**（不弹错、不卡页）
4. **Given** 同一页面多次浏览、内容未变，**When** 重复触发采集，**Then** 按既有去重语义处理（与 F2 桌面端一致）

---

### User Story 2 - 分享面板补盲入库 (Priority: P2)

在 Chrome 安卓（或任何支持系统分享的 App）里看到一个值得留的页面 → 系统分享 → 选「第二大脑」→ 服务端抓取该页正文并入库；随后立刻看到结果（成功/失败）。

**Why this priority**: 覆盖 Firefox 扩展够不着的场景（Chrome 内、微信内"先分享出来"）；独立可用，但不影响 F3 本体的闭环。

**Independent Test**: Chrome 内对若干页面执行「分享 → 第二大脑」→ 入库且正文正确；抓取失败的页面 100% 有明确反馈。

**Acceptance Scenarios**:

1. **Given** Android Chrome 已将系统安装为应用（PWA 安装态），**When** 在任意页面执行 分享 → 第二大脑，**Then** 该页入库（browser 来源、含正文），并显示成功反馈
2. **Given** 目标页无法抓取（登录墙/反爬/非 HTML），**When** 分享该页，**Then** 明确反馈失败原因（或按既定降级语义仅存链接与元信息），不静默空转、不假成功
3. **Given** 未登录或会话过期，**When** 分享，**Then** 引导登录且**不丢分享目标**（登录后继续完成入库）
4. **Given** 重复分享同一页面，**When** 再次分享，**Then** 按既有去重语义处理

---

### User Story 3 - 一次安装、自助更新 (Priority: P3)

用户（唯一使用者）按文档从零完成一次安装：扩展签名 → 手机 Firefox 安装 → 配置凭据；后续版本升级同路径自助完成，且**配置与凭据不丢**。

**Why this priority**: 自用分发路径必须先跑通一次否则 P1 无法落地；但它是使能步骤，独立交付价值低于 1/2。

**Independent Test**: 按文档从零（新设备/清空状态）完整走一遍安装 + 一次版本升级。

**Acceptance Scenarios**:

1. **Given** 一份已签名的扩展包与安装文档，**When** 在手机 Firefox 执行安装流程，**Then** 一次成功且采集可用
2. **Given** 已安装旧版本，**When** 按文档升级到新版本，**Then** 升级成功、配置与凭据保留

---

### Edge Cases

- **Android 后台限制**：Firefox 在后台可能被系统挂起——采集以"页面打开/切换时"触发为主（尽力而为），不承诺后台常驻；长时间纯后台期间的浏览可能漏采（不视为缺陷）
- **移动端能力退化**：桌面扩展依赖的部分后台机制（定时器/常驻后台）在移动端不可靠 → 触发策略以导航事件为主（plan 阶段细化）
- **分享目标未就绪**：系统未处于"安装为应用"（无 PWA 安装态）时分享面板不出现 → 安装引导文案说明
- **分享时手机离线/请求失败**：结果页明确失败并可重试
- **超长页面/大量非语言内容**：沿用 F2 的正文质量过滤与截断语义
- **隐私边界**：采集只含页面内容与元信息，凭据走既有 token 鉴权；黑名单源头过滤在手机端同等生效

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 手机 Firefox 内浏览的页面**自动入库**（标题/URL/浏览时间/正文快照），语义与 F2 桌面端一致（可检索、可引用、进浏览记录与时间清单）
- **FR-002**: 采集凭据与端到端链路复用既有体系；未配置/失效时**静默跳过**（不弹错、不打断浏览）
- **FR-003**: 采集排除规则（黑名单/站点规则）沿用既有配置源，手机端同等生效
- **FR-004**: Android 系统分享面板提供**「分享 → 第二大脑」**：对分享的 URL 由服务端获取正文并入库（browser 来源）；结果以明确成功/失败反馈呈现
- **FR-005**: 分享抓取失败（反爬/登录墙/非 HTML）不得假成功——给出明确失败原因，或按既定降级语义仅存元信息
- **FR-006**: 分享入口未登录/会话过期时引导登录且**不丢分享目标**（登录后继续完成入库）
- **FR-007**: 去重语义与桌面端一致（同 URL/同内容按既有规则处理）
- **FR-008**: 扩展可**自用分发与升级**：签名安装与升级流程文档化、可复现；升级保留配置与凭据
- **FR-009**: 采集故障（网络/服务不可达）不打扰浏览；恢复后继续工作（沿用 F2 队列/重试语义）
- **FR-010**: 手机端系统（PWA 安装态）可用：可安装，并可完成问答/上传/浏览记录查看全流程（结清 001 T029/T030 的移动端验收；分享目标同属安装态能力）

### Key Entities *(include if feature involves data)*

- 无新实体：浏览条目/快照/来源标注完全沿用 F2 既有结构（browser 来源语义、去重、引用体系不变）

## Non-Goals（本次不做什么） *(mandatory)*

- **微信等 App 内置浏览器的自动采集**：无扩展/无系统级入口，仅"手动分享"可达（原 Non-Goal 修订版）
- **Chrome 安卓的自动采集**：平台不支持扩展——自动采集仅 Firefox 路径；Chrome 走分享补盲
- **iOS / Safari**：双端为 Windows + Android，无 iPhone 场景
- **后台保活类手段**：受 Android 电池/后台策略约束，不做常驻保活；漏采按"尽力而为"语义接受（已写入 Edge Cases）
- **扩展公开上架**：仅自用私密分发（unlisted），不做公开商店上架与合规打磨
- **手机端专属管理界面**：采集无感，不新增手机端管理 UI

## Non-Functional Requirements *(include if applicable)*

### Performance
- 采集对手机浏览无明显可感拖慢（异步发起、失败快速跳过）
- 分享入库端到端：秒级返回结果页；抓取超时（可配置）即明确失败

### Reliability
- 采集失败不影响浏览与系统可用（F2 同语义）；分享失败可重试且反馈明确
- 升级路径不丢配置/凭据/待发送队列

### Security
- 沿用 F2 全边界：token 鉴权、只采正文与元信息、黑名单源头过滤、快照按既有语义封存
- 分享入库的 URL 抓取沿用服务端既有抓取安全边界（协议白名单/大小上限/超时）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 手机 Firefox 连续浏览 10 个页面，**≥9 个入库（含正文）**，且全部可在桌面端检索命中/引用（真机端到端）
- **SC-002**: Chrome 内分享 5 个页面，全部入库（≥4 含正文）；失败场景 **100% 有明确反馈**
- **SC-003**: 采集故障演练（断网/服务停机）下浏览**零打扰**（无弹错、无卡顿），恢复后采集继续
- **SC-004**: 从零按文档完成一次安装 + 一次升级，**全程 ≤30 分钟**且无需改代码
- **SC-005**: 手机入库条目与桌面采集**语义等价**：浏览记录时间清单、检索命中、引用抽样全部可用

## Assumptions

- 用户接受"手机日常浏览改用 Firefox"作为全自动采集的前提（既定决策）；Chrome 等场景由分享补盲覆盖
- 可注册 Mozilla 账号以完成自用扩展的私密签名与安装（免费；平台具体流程 plan 阶段核实）
- Android Chrome 支持系统级分享目标（需系统处于"安装为应用"状态）；微信内浏览器仅能手动分享
- 服务端需手机可达：部署后为公网 HTTPS；本地联调期走局域网/临时方案（与 T035 部署协同）
- 复用既有采集端点/token 体系与正文抓取能力；无新表、无迁移
